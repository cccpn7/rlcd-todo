# 桌面待办纸：产品计划

状态：已确定第一版方向，尚未开始功能开发。当前仅完成项目骨架、开发环境和官方示例编译验证。

## 目标与阶段

做一个个人每天愿意看的竖屏桌面待办展示器：抬眼看到今天的重点，翻页看到零散事项和等待回收的反馈。核心价值是让下一步行动持续可见，并逐步减少人工维护。

第一版以手机／电脑网页填写验证使用价值，桌面插电，由 Mac 协助同步。最终由外部助手（大圣）整理事项并通过统一入口推送；具体接入在第一版体验验证后开展。

## 页面与设备交互

采用 300×400 黑白竖屏，类似纸质清单；中文易读和信息层级优先，日期和连接状态保持次要。

| 分类 | 内容 | 排序与操作 |
| --- | --- | --- |
| 今日重点 | 今天值得优先推进的事项 | 不固定为三条，以网页设置的顺序表达优先级 |
| 零散事项 | 临时想起、需要处理的其他事情 | 独立收纳，可在网页移入重点 |
| 待回收反馈 | 已交出去、需要拿到结果的事项 | 标题写清等待对象与结果，例如“合作方：回收测试结论” |

每类可以有多个子页，显示“今日重点 · 1/2”等页码。空分类显示简短空态。长标题换行，超出可用区域时省略，网页可查看全文。字号和每屏容量在首次原型中用真实长度的脱敏样例验证。

- KEY 短按下一页；BOOT 短按上一页；按重点、零散、反馈顺序循环。
- 长按 KEY 返回重点首页；不自动轮播。
- 设备只查看和翻页；新增、编辑、排序、分类、完成、撤销完成均在网页操作。
- 未完成事项跨日保留分类和顺序；已完成事项退出屏幕，在网页保留记录。
- 时区为 Asia/Shanghai。“三页”指三类内容，各类可跨多个屏幕页；重点数量不固定为三条。

## 第一版系统

数据流：手机／电脑网页 → Mac 本地服务 → Wi-Fi → 设备。

网页、设备与 Mac 在同一局域网。不部署公网服务，不加入账号体系、多用户、语音、专注计时或自动抓取平台内容。

### 网页与服务

- 三类事项与设备对应，手机和电脑均可操作。
- 新建要求标题、分类，可添加说明；通过上下移动调整顺序，先不引入复杂优先级标签。
- 支持完成、撤销完成和屏幕内容预览。
- 数据保存于 Mac 本地数据库，服务重启后保留。
- 网页和未来助手复用任务读写接口，设备读取按分类整理好的展示数据。

### 设备

- 使用 ESP-IDF v5.5.2 与 LVGL 9.4.0。
- 每 30 秒检查内容版本，有变化才更新任务画面。
- 缓存最近成功取得的内容，断网或重启后继续显示。
- 显示上次成功同步时间；连续同步失败后提示离线，保留现有事项，网络恢复后自动重试。
- 初次通过电脑配置工具设置 Wi-Fi 和服务地址，不把密码写入源码。
- Mac 休眠或关机期间无法获取新内容；这是第一版接受的边界。

### 外部助手扩展

提供版本化任务读写接口；任务至少包含稳定编号、标题、分类、排序、完成状态和更新时间。为外部来源预留来源名称及来源任务编号，使重复推送更新同一任务而非重复添加。

第一版用模拟推送验证统一入口。大圣侧提取、优先级判断和具体同步冲突策略在接入阶段定义，不在本轮实现。第一版手动排序，不自行推断用户承诺或任务重要性。

## 协作流程

产品负责人负责场景、优先级和体验取舍，Agent 负责设计细化、实施、验证和记录，不要求负责人预先编写完整 PRD 或选择技术框架。

| 阶段 | 产品负责人提供与判断 | Agent 交付 |
| --- | --- | --- |
| 真实内容 | 10–15 条覆盖三类的事项与重点顺序；真实内容仅本地处理 | 整理表达，识别长标题与模糊事项，生成公开使用的脱敏样例 |
| 屏幕原型 | 重点是否突出、字是否清楚、翻页是否顺手 | 竖屏原型和按键流程 |
| 最小闭环 | 在网页修改事项并观察实物变化 | 网页、服务、同步、显示与缓存 |
| 日常试用 | 连续使用 3–5 个工作日，反馈具体场景 | 调整信息量、操作与同步体验 |
| 助手接入 | 助手输出样例和可用对接方式 | 将输出接入统一任务接口 |

反馈优先描述实际问题，例如“开会回来找不到下一步”“等待反馈的事项忘记追”“每天维护太费时间”。需求说明、交互规则和验收清单由 Agent 维护，产品负责人决定关键取舍。

## 验收

- 正常坐姿与桌面光线下，能快速看清事项和顺序。
- 三类、空列表、长标题、多屏列表均能正确显示与翻页。
- 网络正常时，网页保存后 35 秒内更新；完成、撤销、排序一致。
- Mac 休眠、网络断开、设备重启后仍可查看最近内容，重连后恢复同步。
- 跨日保留未完成项；重复外部推送不产生重复任务。
- 试用后用户愿意继续使用，并能指出它帮助找回重点的实际时刻。
