# 桌面纸鱼缸：SS49E 磁感应喂鱼实施计划

2026-11-23 用户批准。网页原型试样07已获用户确认，进入固件与服务联调。固件已实现、编译并烧录，兼容服务已部署；SS49E 已接线并校准，用户确认首次磁感应喂鱼正常，设备记录确认180秒返回。原型通过不等于真屏验收，最新规则已由用户真屏确认并授权提交；30次专项重复测试、长时间稳定性和完整通信回归仍需补测。原型入口与启动方式见 [交互原型](../prototypes/aquarium/README.md)。本计划替代产品计划中的常驻待办显示规则，既有数据、字体、联网及隐私约束继续有效。

## 使用体验

平时显示 300×400 黑白像素鱼缸：3 条小鱼自由游动，少量水草和气泡。不加入饥饿、死亡、金币、声音或养成系统。

原型外观按用户最新反馈：小鱼放大到初稿的1.5倍，三条鱼身分别写“思”“闪”“点”，按用户最新参考图采用白身黑色轮廓、分叉尾巴、背鳍／腹鳍和大眼睛，黑字标名，转向不镜像文字；追食略放慢、每口停顿略加长。预览主体约54×28px，14px字，真屏文字辨识仍需后续验收。

鱼粮瓶靠近顶部 → 鱼粮从画面上方落下 → 小鱼追逐并吃完 → 待办轮播 3 分钟 → 自动回鱼缸。

- 最新反馈要求进一步放慢：追食60px/秒，每口停顿650ms，鱼粮沉降相应放缓。取消原6–8秒目标，以实际吃完为准，再停留900ms进入待办；不凭超时删除剩余食物。鱼要真正追逐并由嘴部接触吃掉颗粒。
- 鱼身采用覆盖尾巴和鳍的56×32px碰撞范围，位置以身体中心计算，转向不跳位；鱼缸边界约束、鱼间分离与绕行同时生效。其他鱼挡住目标时选择可到达的食物，避免重叠或堵死。
- 鱼粮需要比初稿清楚、更大，且大小不一。2026-11-23 根据用户提供的参考截图，将原型修订为 24 颗约 4–10px 的混合鱼粮，以空心圆环搭配实心碎粒，分批从顶部中间撒下、向两侧散开并轻微摆动；小鱼逐颗追食，喂食节奏按后续慢速反馈调整。截图用于外观参考，未观看视频，运动节奏为本项目设计；最终效果待用户确认。
- 从待办首页实际完成刷新时起，使用单调时钟计时 180 秒。三分类的所有实际子页各展示 5 秒，包括空分类，保留标题 26px、正文 24px／行高 32px 和完整原文分页。
- 喂食期间忽略新的喂鱼动作，不排队、不重播。在鱼缸或待办页面，新的磁铁靠近或 KEY 短按都立即进入喂食；吃完回到待办重点首页，从实际刷新成功重新计时180秒。持续靠近不连发，必须移开500ms后再靠近150ms；返回鱼缸后也须重新观察释放。
- 启动默认鱼缸；鱼位置不保存，已发布待办缓存保留。无缓存时喂食后显示“暂无已同步待办”，180 秒后返回。
- 新版本在鱼缸／喂食期间只更新缓存；待办模式收到后刷新重点首页并重启该页 5 秒停留，但不延长原有 180 秒期限。
- KEY 短按在鱼缸与待办中均为喂鱼，不再承担下一页；待办保留 BOOT 上一页、KEY 长按首页和5秒自动翻页。翻页、返回首页及新发布不延长期限，重新喂鱼后的新一轮待办重新计时；喂食期间忽略按键触发。
- 配对与维护提示沿用安全要求；覆盖层不得让待办 180 秒期限被无限延长。具体覆盖层交互在固件联调时验证。

## 霍尔感应与安装

SS49E 为模拟线性霍尔传感器，以 ADC 测量磁场变化，不当作数字开关接入。

| 连接／参数 | 约定 |
| --- | --- |
| 电源 | 3.3V，共地，电源旁 100nF 去耦 |
| 模拟输出 | GPIO1／ADC1_CH0，ADC 输入按原厂建议滤波 |
| 采样 | 20ms，滤波后与无磁基准比较绝对差，兼容两种极性 |
| 校准 | 首次安装采集“移开”和“目标靠近位置”，验证区分度并保存基准及触发／释放阈值 |
| 防抖 | 靠近连续 150ms；离开连续 500ms 后才重新允许 |
| 故障 | 采样故障不触发；未校准不能把上电附近磁铁当作背景 |

接线前必须按实际封装和原厂引脚图核对 VCC/GND/OUT；模块使用 AO，不凭线序猜测。先顶部临时固定试装，实测磁铁方向、距离和外壳干扰，再制作顶部支座及瓶体。保留现有外壳主体，磁铁固定在瓶内，避开 USB 插头和屏幕受力区。不能只依据型号承诺触发距离。

参考：[SS49E 原厂规格书](https://prod-edam.honeywell.com/content/dam/honeywell-edam/sps/siot/en-us/products/sensors/magnetic-sensors/linear-and-angle-sensor-ics/common/documents/sps-siot-ss39et-ss49e-ss59et-product-sheet-005850-3-en-ciid-50359.pdf)、[ESP32-S3 硬件指南](https://documentation.espressif.com/projects/esp-hardware-design-guidelines/en/latest/esp32s3/schematic-checklist.html)。

## 固件与同步边界

统一管理 aquarium／feeding／todo 三个显示状态。动画设备本地执行，目标 12 帧／秒；固定鱼和食物数量，复用帧缓冲，不逐帧分配内存。动画、计时和采样不得被网络等待阻塞。保持实物整体旋转 180°，逻辑截图正向。鱼缸保留小号日期和 Wi-Fi／HTTP 状态，隐藏待办页码；左上角用48×32px纯黑白“斑鱼”图形替代“小鱼缸”文字，借鉴用户提供的斑马标志的条纹和笑脸，并改为鱼尾和鱼鳍。待办模式保留分类标题。

数据通路仍是服务端唯一清单与不可变发布、设备双缓存、HTTPS 长轮询；USB/BLE 只补发同一版本。不新增远程喂鱼接口，断网照常喂鱼和查看最近有效缓存。

**收到内容不等于展示内容。** 回执和状态接口须区分保存版本、已展示版本和当前显示模式：

| 状态 | 成立条件／用户文案 |
| --- | --- |
| 等待同步 | 已发布，设备尚未确认持久化 |
| 已同步、待查看 | 完成完整性校验和双缓存写入，尚未在待办模式刷新该版本 |
| 已在待办模式展示 | 真正进入待办并完成该版本画面刷新后回执；不表示当前仍在显示待办 |

新版接口兼容旧固件回执。精确定义新增字段、重启与重试语义，并添加跨版本测试后再上线。设备截图仍反映当前画面，不能用缓存待办截图假装设备正显示待办。网页、大圣 Skill、结果通知和 USB/BLE 维护工具一同改文案；后台静默同步不得声称“待办已显示”。

部署顺序：先兼容服务，后固件，再检查真实更新与旧维护通路。远端仅操作本项目隔离目录、虚拟环境、数据库和 Supervisor 程序；授权 Skill 变更先备份后最小补丁，不重启或升级 OpenClaw、网关或其他服务。已有 Wi-Fi 离线问题另行记录，不因本地动画完成就宣称修复。

## 实施阶段

1. **浏览器原型（已确认）**：原创黑白像素鱼，模拟持续靠近、移开、追食、三分钟待办及返回。确认鱼形、密度、节奏后进入固件。浏览器示例不接真实清单，不代表实际驱动／字体／帧率验收。
2. **感应实测**：核对实物、接线、ADC 基准／靠近采样、临时安装及阈值保存。确认稳定触发与释放。
3. **固件和服务联调**：显示状态、动画、异步同步、回执及客户端文案；读取开发文档，先本地测试、编译，备份后按部署顺序更新服务和烧录。
4. **真屏验收和 Git**：核对方向、字体、感应、吃食和三分钟往返；完成稳定性测试、记录限制，用户接受实物后提交并推送。禁止提前提交固件。

## 当前证据与限制

浏览器纯逻辑测试覆盖慢速逐颗吃完、鱼间碰撞与绕行、嘴部接触和进食间隔、180 秒期限、手动翻页不延期、持有磁铁与锁定期间动作不重放、5 秒轮播和 30 组不同初始游动位置。它们不等于实物 30 次感应测试。原型不模拟网络发布、ADC 校准、真实长文分页或固件缓存。

浏览器自动连接曾超时，最终由用户直接体验并确认。固件移植后通过100组追食／碰撞模拟、霍尔两极性与故障保护测试、文本完整性测试及编译；服务端包括旧固件兼容和新回执测试在内25项测试通过。远端仅重启 rlcd-todo，保护进程 PID、OpenClaw 配置及已有 cron 摘要复核一致。以上不替代实物接线、烧录、真屏和8小时测试。

### 首轮真屏联调与帧率修正

完整16MiB设备备份及摘要校验完成，首次全量烧录包含新增14px标名字库，原待办缓存和绑定保留。启动回报 aquarium、保存版本保留、展示版本0、霍尔未校准禁用。用户反馈首版帧率很低，实际仅4.86fps。

定位到鱼缸每帧沿用1bit→RGB565→LVGL→逐像素旋转的通用链路开销。改为动画专用的原生1bit绘制与4×2字节打包，直接SPI输出；待办保留LVGL。主机独立参考逐一验证120000像素、180°方向与缓冲区边界。优化版再次烧录后测得11.22fps，单帧约23ms（绘制约5–6ms、转换/传输约18ms），接近12fps目标；这是程序刷新测量，最终流畅程度仍待用户真屏确认。

持续观察已启动但尚未满足8小时。既有Wi-Fi仍处于连接中，不能宣称无线链路或离线问题已经修复。尚未提交Git。

### 待办中重新喂鱼（2026-11-23）

用户要求待办显示期间也能使用磁铁或 KEY 回到鱼缸喂食，再进入待办。固件与网页原型同步采用上述规则；仅喂食中忽略重复触发。新规则已烧录；首次实测发现待办中感应无法重新就绪，优化待办刷屏后，现场记录多次待办→喂食→待办且重新计时，用户确认正常并授权提交。
