# 待办鱼缸：钓一件事来做

2026-11-27：布局02获确认，批准进入开发；补充保留原有3条带“思、闪、点”的常驻鱼和原有水草。当前固件已烧录，用户确认整体效果满意并授权提交；具体软件、通信与实物验证范围见验证文档。

## 核心体验

鱼缸持续作为主画面。每件未完成待办对应一条鱼；想开始做事时钓出一条，揭晓任务，提竿后自动把鱼放进水面旁的鱼护。鱼护旁立小牌子提示正在做的事项；在大圣或网页完成后，同步让对应的鱼消失。

## 已确认的产品规则

- 默认3条常驻鱼保留原有形状、尺寸与“思、闪、点”文字，原有水草保留；不对应任务，不参与抽取，不因任务完成消失。
- 每件未完成待办对应一条任务鱼，鱼身不写任务内容。
- 只有“今日重点”和“今日杂项”的未完成任务可以抽取；“今日追踪”不参与抽取。
- 将可抽取的重点与杂项合并为一个池，按任务等概率随机；不先选分类、不优先抽重点，也不让鱼的位置、大小或游速影响概率。
- 一次只接一件正在做的任务，对应鱼进入水里的鱼护，不再参与抽取。鱼护旁的小牌子显示“正在做”及对应任务。
- 钓出、入鱼护都不等于完成。完成仍在大圣或网页操作，设备收到同步后才让鱼消失；不增加设备按键完成任务的入口。
- 日常以鱼缸为主，不继续默认三分钟整份清单轮播。喂食保持每次12颗、可追加、落底未吃消失，结束后留在鱼缸。有当前任务时，喂鱼先将鱼护中的鱼放回池子、牌子复位；任务仍未完成，重新加入抽取池。
- 道具方向为N极喂鱼、S极钓鱼；实际磁极映射与触发距离须按安装位置验证。

## 鱼护与任务牌

鱼护放在右上角水面旁，缩到与小鱼相近的大小，表现为挂在水面的迷你网兜。鱼被收进后仍会轻轻游动。鱼护内的鱼仍是那件任务对应的同一条鱼，不额外复制一条。

旁边立一块小牌子：

> 正在做
> 整理评审材料

牌子承载任务文字，新增任务鱼身保持无字，常驻鱼保留原有字。右下位置保留，斑鱼标志放在牌子上，正文先用18px；长原文提供完整查看／翻页入口，不靠缩小字体硬塞，也不把省略内容当完整任务展示。收起详细任务牌后，鱼护旁的小牌子仍保留。

鱼护空时保持为空，小牌子显示“钓一件事来做”，并提示长按看清单。

## 第一版流程

1. **任务入缸**：新清单发布并同步后，未完成事项成为任务鱼；网页草稿不提前变鱼。任务编号保持关联，改标题不会换一条新鱼。
2. **喂鱼**：N极鱼粮瓶靠近或KEY短按，鱼护有鱼时先持久化清空当前任务，再让同一条鱼用约0.9秒游回池子，牌子回到初始空态，并正常撒12颗粮。放回不完成、不删除任务。鱼护为空则照常喂食；钓鱼动画期间仍忽略喂食。
3. **下钩抽取**：鱼竿靠近，鱼钩从屏幕最上方垂下；下落到位后先等约2秒，鱼继续自由游动，再让等概率选中的任务鱼游来咬钩。持续靠近不重复抽取，移开后提竿揭晓。
4. **揭晓任务**：提竿后短暂展示钓到的任务，不再提供“就做这个／放回”确认；直接记为正在做，完整原文显示在任务牌上，长内容可翻页。
5. **入鱼护**：提竿揭晓后，鱼自动进入右上水面旁的鱼护，小牌子显示正在做的任务。任务保持未完成，暂时从抽取池排除。
6. **实际做事**：鱼缸保持显示。再次钓鱼时，展示鱼护里的当前任务并翻到牌子下一页，不另外积累第二件。不提供额外的放回按钮；喂鱼可将当前任务鱼放回池子，牌子复位后可再钓。
7. **同步完成**：在大圣或网页完成事项，设备收到确认后的最新状态，鱼护里的鱼做简短离场动作并消失，小牌子恢复空态，可以再钓下一件。

鱼护中的任务被改名时，小牌子同步更新；钓到及入护均不算完成。

## 任务与鱼的关系

| 对象／状态 | 鱼缸表现 | 是否可抽 |
| --- | --- | --- |
| 默认3条常驻鱼 | 自由游动、吃鱼粮 | 否 |
| 未完成的重点／杂项 | 一件一条任务鱼 | 是，等概率 |
| 当前正在做 | 同一条鱼留在鱼护，小牌子显示任务 | 否 |
| 已完成事项 | 同步后对应鱼消失 | 否 |
| 未完成的追踪事项 | 沿用“一件待办一条鱼”时仍在缸中，外观同其他任务鱼随机分配 | 否 |

六种外观随机分配，不通过鱼形或花纹暗示分类；任务池负责排除常驻鱼与追踪事项。

## 边界与待讨论细节

- **没有可抽任务**：提示“暂时没有可钓的事项”；即使还有追踪鱼，也不能说全部任务已完成。三类全部完成时只剩3条常驻鱼。
- **撤销完成**：同步后任务鱼回来；回到自由游动区，不自动占据鱼护。
- **远端删除或改分类**：删除则移除对应鱼并提示“任务已同步”；正在做的任务被移到追踪时，退出鱼护并按不可抽处理。提示“任务已同步”。
- **离线**：可看最近内容，但不能提前把鱼消失当成完成同步。联网后按大圣／网页的最新已发布状态更新，不用本地旧状态反向覆盖任务。
- **重启与任务关联**：保留鱼护内任务的稳定编号；重启后先恢复最近状态，再通过同步核对任务是否仍未完成。
- **抽取公平性**：只在本次下钩时选择一次；网络重试、动画刷新和移动鱼竿不重新抽。不增加“放回重抽”确认。
- **空间容量**：300×400屏幕新增鱼护和牌子后，可游动空间更少。先用3、8、15件待办做原型，检查鱼、鱼护和任务牌是否清楚，不悄悄把多件任务合成一条鱼。
- **清单入口**：保留主动查看完整清单与当前任务原文的方式，紧急任务不必等待随机钓中；KEY长按进入完整清单（保留5秒分页与180秒返回）；再长按返回鱼缸。BOOT短按在清单中上一页、在鱼护有任务时翻任务牌。鱼护为空时BOOT短按下钩，再短按提竿。

## 实施与验证

- 固件：N极为当前安装方向下正偏差，S极为负偏差。继承原灵敏度、150ms触发、500ms释放；采样失效不作提竿。开机须先释放磁铁。磁极需实物复核。
- 下钩：下落800ms，到位等2000ms，再用1100ms游来咬钩；咬钩前移开是空钩，不接任务；咬钩后移开提竿，保存成功才自动入护。持续放置不重复抽取。钓鱼过程不接收新的喂食，游动时每次喂12颗、允许追加。
- 保存：鱼护任务ID单独写NVS，写入失败提示重试，不伪装已接下。最新发布中缺失、完成或移到追踪的任务退出鱼护；改名保持同一条鱼。恢复已完成任务后回自由区。
- 同步：沿用唯一发布与RTD4稳定ID，不修改服务端任务完成规则。当前任务保存在设备；维护状态可查询ID、鱼数和钓鱼阶段。鱼缸、钓鱼与任务牌不宣称完整发布已展示，主动清单显示继续沿用既有展示回执。
- 字体：原生18px覆盖与24px相同的字符集，字体分区扩为6MiB，起始地址不动；NVS与双缓存地址不动。先备份，再刷应用、分区表及字体。
- 验证：等概率候选、无候选、提前提竿、完成/删除/改分类/改名、撤销后入缸、保存失败、重启恢复、N/S防抖、全文分页和像素边界。烧录后由用户检查鱼形、水草、磁铁、提竿与任务牌；接受后才提交Git。
