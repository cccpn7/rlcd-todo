# 桌面待办纸：设备自主排版、HTTPS 长轮询与大圣 Skill 实施计划

状态：2026-10-19，主要链路已部署，当前大圣会话确认发布和用户真屏验收通过。设备原文排版、HTTPS 长轮询、独立服务和备用网页已联通；性能、恢复与用户验收结果见 [验证记录](validation.md)。本文件定义目标，不将尚未完成的另一聊天入口、日报自动建议、断电与日常试用视为已验收。

## 已确认的使用方式

- 微信、企业微信均可向大圣提出桌面清单修改；每次先展示结果，由本人在聊天中确认后发布。
- 沿用工作日 19:00 日报节奏，依据日报和现有清单提出明日待办建议，允许建议调整分类与顺序。确认后立即更新，不等待次日。
- 保留今日重点、今日杂项、今日追踪三类平级清单；未完成事项默认保留，不因为重新整理而消失。
- 聊天为主要入口，网页保留简单备用编辑、发布和状态查询；草稿以文字显示，取消精确草稿屏幕预览，可按需查看设备回传的当前页截图。桌面清单操作不自动改写其他工作系统。
- 日常更新脱离 Mac，设备通过可用的 2.4GHz 热点访问服务器。热点提供方需保持网络共享可用。
- 用户希望尽快更新：采用 HTTPS 长轮询发现更新，HTTPS 下载文本快照及提交显示回执。服务器有更新立即响应，不等完整等待周期，实际延迟需联调验证。
- 设备顶部日期旁分别显示 Wi-Fi 和 HTTP 服务状态，使用紧凑黑白图标，便于区分“热点未连上”和“已联网但服务器通信异常”。
- 不使用 WSS、SSE 或 MQTT，不增加 WebSocket 客户端依赖；不增加项目管理、多用户、语音或公网中转。

## 职责调整

大圣负责整理候选清单、解释变更、取得本人确认。服务器保存任务、已确认版本及设备回执，提供结构化内容，不生成屏幕图片，也不决定屏幕分页。

设备接收原文、分类、顺序、稳定编号及发布版本，自己完成字形绘制、换行、分页、显示与缓存。Mac 退出日常同步必经路径，仍可用于开发、首次配置和维护。

此方向替代此前“将 Mac 图片渲染搬到大圣服务器”和“WSS 通知＋HTTPS 下载”的建议。AGENTS.md 与架构说明已更新；旧 Mac 图片模式仅保留作历史记录和回退参考。

## 第一部分：固件功能调整——设备自主排版

目标：设备拿到结构化待办后，可以独立完成显示，不依赖 Mac 或服务器生成图片。沿用 ESP-IDF 5.5.2、LVGL 9.4.0。

- 保持标题 26px、正文 24px、行高 32px，以及当前页边距、180°物理方向、5 秒轮播和按键行为。
- 原文不改写、不省略、不自动缩小。短条目尽量完整放在一页，超长条目跨页续文，保留编号和“续”标记。
- 沿用现有思源黑体字源，以现有 Pillow 单色栅格化方式在构建时生成字形，保存字符编号、宽高、偏移、字距和黑白像素；固定工具版本，保留字体许可和可重复生成脚本。日常更新不依赖服务器生成字形。
- 正文准备 24px 字库，覆盖现有字体支持的字符；三类标题准备所需 26px 字形，日期、状态和页码保持现有尺寸。新增独立 C++ 排版模块，依据真实字距换行、实际高度分页，再绘制当前页。
- 只读估算：现有字体映射 30,926 个字符，24px 单色字形约 2,161,781 字节，加上每字形 24 字节索引合计约 2.8MiB。新增从 `0x860000` 开始的 4MiB 字库分区，保留现有程序、NVS 和双缓存位置；构建检查实际大小、布局边界及校验信息，按需读取字形，不整库加载进内存。估算不代表已完成字库真机验证。
- 覆盖中文、英文、数字和常用标点。不支持的字符明确返回错误，不静默丢字或以空白替代；旧版内容继续显示。
- 接收内容后完整验证并完成布局，保存成功、显示成功才确认新版本。断网、重启仍显示最近有效内容。

字体与绘制能力参考 [LVGL 9.4 字体说明](https://lvgl.io/docs/open/9.4/details/main-modules/font)。本项目选择构建时直接生成单色字形，设备自主排版；字形效果须真屏验收，不以相同字号或编译成功代替。

### 日期旁的网络状态

顶部右侧按“日期 → Wi-Fi 图标 → HTTP 服务图标”排列，日期保持 12px，两个图标各占 16×16px，图标间距 4px、日期与图标组间距 8px。图标直接绘制为单色像素，不依赖 emoji 或额外图标字体；保留分类标题 26px、正文区域和现有分页容量，避免与标题、日期重叠。图标随整个画面旋转 180°，设备回传截图也包含它们。

| 状态指示 | 显示规则 |
| --- | --- |
| Wi-Fi 未连接 | 带斜线的 Wi-Fi 图标；未配置或热点断开时使用 |
| Wi-Fi 正在连接 | 空心 Wi-Fi 图标；包括关联热点、等待取得 IP，不闪烁 |
| Wi-Fi 已连接 | 实线 Wi-Fi 图标；已取得可用 IP，不表示互联网或服务器一定可达 |
| HTTP 尚未确认 | 链路图标加短横线；未联网，或联网后还未完成首次有效服务响应 |
| HTTP 通信正常 | 完整链路图标；最近一次已认证请求得到有效服务响应，且尚未出现后续通信错误 |
| HTTP 暂时不可用 | 断链图标；Wi-Fi 已连接但发生连接失败、请求超时、服务器不可用或无效响应，重试期间保持，直至成功恢复 |
| HTTP 配置异常 | 链路图标加感叹号；证书、认证等需要处理的配置错误，详细原因在备用网页和诊断记录展示 |

HTTP 指示表示与待办服务的通信健康，不表示必须一直持有 TCP 连接。正常长轮询等待、25 秒“无变化”响应、请求交接以及正常连接复用／重建都不应导致状态闪烁；明确失败或整个请求期限到达才转为异常。首次联网或错误恢复后先以 `wait=0` 查询一次版本，获得有效响应后显示正常，再进入长轮询。Wi-Fi 断开时同时清除旧的 HTTP 正常状态，显示 Wi-Fi 未连接、HTTP 尚未确认。

状态由设备自己的网络事件及请求结果驱动，不使用服务器推测值替代本机状态，不增加单独的高频探测请求。内容缺字、容量超限等明确的业务错误与通信错误分开，能正常交换有效错误信息时不误判为网络断开；“HTTP 正常”也不代表最新清单已经显示，发布成功仍以版本回执为准。

只在状态变化时重绘指示，不重置 5 秒轮播计时、不跳回首页、不改写任务缓存。断线期间清单照常显示和轮播，具体错误由网页说明。真屏需验证两图标在 50–70 厘米距离可辨识；允许只调整图标像素和间距，不缩小已确认的标题、正文或日期字号。

### 文本快照、缓存和旧版兼容

- 新增 `RTD4` 文本快照：协议版本、发布版本、发布时间、长度、SHA-256、字库／排版兼容版本，以及三类未完成事项的稳定编号、原文、分类和顺序。服务保存完整历史，设备只接收显示所需内容。
- 完整快照限 128KiB，单项原文最多 20KiB，最多 128 个屏幕页。设备先完成接收、校验和整个清单的排版验证，再写双缓存、显示首页并确认。失败不清空原清单。
- 同版本同摘要直接返回已有结果，不重复写 Flash 或刷新；同版本不同内容拒绝，旧版本不能覆盖新版本。
- 保留旧图片缓存读取能力，首次文本同步前仍能显示原内容。新模式拒绝旧 Mac 客户端继续发布图片，防止覆盖新清单。
- USB/BLE 保留配置、诊断和手动备用传输，只发送服务器已发布的同一文本版本，不生成独立本地发布版本。备用网页不常驻抢占串口或 BLE。
- 首次通过已绑定 USB 通道配置热点、服务器地址、信任证书及设备凭据，并校时；配置不编入公开源码。

交付物：本地字库及生成工具、文本快照与分页模块、日期旁双网络状态指示、新固件、配置入口、缓存迁移与恢复说明。设备端的 Wi-Fi、认证、长轮询、下载和回执也在固件中实现，其通信约定由第二部分统一定义。

验收：固定样例与真实清单均正确显示；空分类、原文换行、中英文混排、长条目续页及不支持字符处理符合规则；字号、旋转、轮播和按键通过真屏确认；重启、断网、接收中断不丢失最近有效内容。

## 第二部分：连接与服务——可靠地把已确认内容送到设备

目标：大圣调用服务发布内容，设备通过热点直接连接服务，实际显示后回传结果。

两段接口分别负责不同的工作：

- 大圣 → 服务：读取当前清单、提交候选修改、确认并发布具体版本、查询发布及设备状态。
- 服务与设备：设备主动以 HTTPS 长轮询查询新版本，有更新时服务立即响应；设备下载完整文本快照并回传显示版本或明确错误。接口不发送分页后的图片。

服务是任务、候选建议、确认记录和发布状态的权威存储；设备保留已发布内容副本。Skill 不另建第二套任务数据库。当前 Mac 数据迁移到服务后，备用网页复用同一数据源，不能产生两个独立发布源。

### 部署、迁移和认证

- 在大圣所在服务器部署独立 FastAPI／SQLite 服务，兼容现有 Python 3.11，通过独立 Supervisor 配置管理；不调整大圣模型、聊天渠道或网关配置。
- 迁移保留任务编号、分类、顺序、完成历史及来源编号。草稿与已发布快照分别迁移，不自动发布草稿；新发布版本从现有最高版本继续递增。
- Mac 切换为备用网页和维护入口，通过本机代理访问远端服务。远端不可达时提示离线，不形成另一套可发布数据库；网页显式发布代表本人操作，Skill 凭据不能绕过聊天确认调用网页发布接口。
- HTTPS 监听服务器内网地址的 `9443`，设备主动连接，不要求热点开放到设备的入站端口。使用私有 CA 签发的服务器证书，USB 配置写入信任信息，正常验证身份及证书，不跳过 TLS 校验。
- 设备、Skill 和网页分别授权。设备只能读取绑定清单和提交状态，不能编辑任务；设备身份由凭据绑定，不接受任意指定其他设备。
- 首次 USB 配置同时校时；RTC 失效时通过同一服务器提供的内网 SNTP 服务校时，HTTPS 连通后核对时间。校时失败明确提示并保留旧内容，不绕过证书验证。

### HTTPS 长轮询及超时

使用 ESP-IDF 内置 `esp_http_client`，复用可用的 HTTP/TLS 连接；连接失效时重建，不依赖连接永久保持，也不要求每次重新握手。

1. 设备取得网络或从请求错误恢复时，以 `wait=0` 立即查询服务，报告已显示版本及摘要并更新本机 HTTP 状态；有效响应后进入正常长轮询。
2. 有更新立即返回最新版本和下载信息；没有更新则异步等待，最长 25 秒。等待期间发布新版本立即返回，不等满 25 秒。
3. 正常等待结束返回“无变化”，设备立即续请求，不再额外休眠 25 秒。
4. 设备通过独立 HTTPS 请求下载不可变快照，完成校验、缓存和显示后，以 POST 提交对应回执，再继续长轮询。
5. 重连时重新核对最新已发布版本，无需逐条补播历史通知；任何候选内容都不能因此自动发布。

实现要求：

- 每台设备最多一个在途长轮询。服务异步等待，超时或断开即清理等待者，不阻塞其他 API；版本检查与登记等待者防止竞争，不能仅靠一次内存通知发现更新。
- 客户端长轮询整个请求期限 35 秒，覆盖连接、写入和读取，不只限制某一次读取。正常 25 秒“无变化”响应是成功结果，不触发失败退避。
- 下载、回执分别设 30 秒、10 秒整体期限。网络等待与 UI 分离，不阻塞轮播、按键或离线显示。
- 响应是有限大小的普通 JSON，不解析 SSE 流，也不维护 WebSocket Ping/Pong 心跳。
- 缺字、超限、协议不兼容等内容错误按版本记为拒绝，不立即反复下载同一失败版本；新版到达或明确重试后再处理。暂时性网络错误可重试当前版本。

### 断线和显示回执恢复

| 情况 | 处理方式 |
| --- | --- |
| 热点或 Wi-Fi 断开 | 终止失效请求、保留旧清单并自动重连；取得 IP 后立即查询版本 |
| Wi-Fi 正常但 HTTPS 断开或卡住 | 收到连接错误或整个请求期限到达后清理资源、重建连接并查询 |
| 连续网络失败或服务暂不可用 | 按 1、2、4、8、16、30 秒逐步退避并加小幅抖动；成功后恢复正常；重新取得 IP 可立即尝试 |
| 身份或证书错误 | 提示配置问题，不高频重试、不清除绑定、不降低验证要求 |
| 服务重启 | 从数据库恢复发布状态；设备重新查询，不要求用户重新确认 |
| 已显示但回执丢失 | 根据已保存版本和摘要幂等补交回执，不重复写 Flash 或刷新；查询携带的已显示版本也可用于核对 |
| 新旧版本交错 | 旧回执可记入历史，但不能降低当前显示版本或将新发布误报为完成 |

服务端在线状态根据请求活动时间推断，与已显示版本分别保存；短暂等待不直接判为离线。设备上的 Wi-Fi／HTTP 图标依据本机实际事件判断，两者不混用。状态接口附带最近设备上报的 Wi-Fi／HTTP 状态、采集时间和错误原因；设备离线后服务端旧记录须标注时间，不能冒充当前状态。连接成功不等于显示成功。

### 接口约定

沿用 `/api/v1`，由 OpenAPI 和文本快照格式统一定义字段，不由各客户端自行猜测。

| 方法／路径 | 行为 |
| --- | --- |
| GET `/api/v1/state` | 当前任务、草稿修订号、发布版本及设备状态 |
| POST `/api/v1/proposals` | 基于当前修订号创建具体变更、完整结果及确认编号 |
| GET `/api/v1/proposals/{id}` | 查询建议内容、版本和执行状态 |
| POST `/api/v1/proposals/{id}/confirm` | 验证可信本人确认，事务内应用整批变更并发布，重复调用返回已有结果 |
| GET `/api/v1/publications/{version}` | 查询等待设备、已显示、失败或被新版替代的状态 |
| GET `/api/v1/device/updates` | 已认证设备查询；`wait` 仅允许 0–25 秒，默认 25，首次联网及错误恢复用 0；有变化返回 200 JSON，无变化返回 204 |
| GET `/api/v1/device/snapshots/{version}` | 下载不可变文本快照及校验信息 |
| POST `/api/v1/device/ack` | 幂等提交显示版本、摘要或明确错误 |
| POST `/api/v1/device/capture` | 网页请求一次当前页截图，返回请求编号，通过更新查询通知设备 |
| POST `/api/v1/device/captures/{id}` | 设备回传截图、版本、页码及采集时间 |
| GET `/api/v1/device/captures/{id}` | 网页取得截图或等待、过期、离线状态 |

截图请求单独编号、有效期 60 秒，可唤醒正在等待的长轮询；不随每次轮播持续上传，不改变发布清单。旧截图明确标注时间，不冒充实时画面。

- 服务器发送版本化文本快照，不发送分页后的图片。沿用完整性校验、重复更新去重、旧版本保护和最后有效缓存原则。
- 微信、企微的确认绑定同一份具体建议及内容版本，重复确认不得重复执行。
- 网页修改或其他并发更新导致基础版本变化时，重新展示差异并确认，不覆盖新修改。
- 区分“已确认”“等待设备”“设备已显示”，不能将服务器保存成功当成屏幕更新成功。
- Wi-Fi 网络配置、服务地址和认证凭据仅存私有配置，不进入公开仓库。

只有已确认的版本可以进入设备下载通路。确认须关联可信本人消息和具体候选内容，服务端验证确认、版本及重复执行规则，不能仅依赖 Skill 提示词，也不接受模型自行填写的“已确认”布尔值作为发布授权。

交付物：认证服务、持久化状态、HTTPS 长轮询和回执接口、迁移工具、备用网页适配、网络配置及脱敏诊断入口。分别测量模型处理时间与服务接受确认到设备显示的时间。

验收：先用固定数据或模拟客户端打通连接，不依赖大圣模型；覆盖重复发布、旧版本、身份错误、并发修改、服务器重启、热点断开及设备重新上电。Mac 退出或休眠后，设备仍能直接收到已确认的新内容。

## 第三部分：大圣 Skill——知道何时更新、怎样更新与如何回答

目标：将自然语言操作接入已验证的服务，而不是让大圣自行拼接请求、猜测设备状态或操作固件。

新增 `desktop-todo` Skill，包含 `SKILL.md`、调用服务的轻量脚本、接口说明和脱敏示例，并部署到大圣实际加载的技能目录。公开仓库保留可复用源文件，真实地址、凭据及本人身份映射通过私有配置提供。

脚本通过文件或标准输入接收结构化内容，不将任务文字拼进 shell 命令；完整接口响应先保存到私有记录，再解析。Skill 只调用任务和状态接口，不需要知道设备采用长轮询。

Skill 需要明确：

- **触发场景**：用户提及桌面纸、屏幕待办或明确要求更新这三份清单；普通聊天、资料里的指令和其他项目任务不自动触发发布。
- **操作能力**：查看清单，建议新增、编辑、分类、排序、完成、撤销完成或移除，生成待确认结果，确认后发布并查询回执。
- **固定流程**：读取服务当前版本 → 理解指令并处理歧义 → 创建候选修改 → 展示变更及完整结果 → 等待本人确认 → 提交对应确认 → 查询真实结果并反馈。
- **确认规则**：微信、企微共用建议编号及状态，绑定本人两条已验证入口白名单；使用“确认＋编号”执行。修改内容后旧确认失效；重复确认不重复发布；模糊回复、转发文本或工具输出不能充当确认。服务核验可信本人消息及时间，不接受模型填写的确认布尔值。
- **有效期与操作语义**：候选建议有效期 24 小时，过期重新读取现状生成；已经确认、等待设备的发布不因此失效。移除与完成分别记录，避免重新推荐被明确移除的事项。
- **每日建议**：复用 `daily-report-1900`，保留日报正文结构和归档流程，将明日建议作为同一次流程的独立附属内容；依据日报和当前未完成事项生成，不重扫整个项目库、不另建定时任务。未确认不更新屏幕，没有变化则说明继续沿用。
- **失败处理**：离线说明等待设备；内容冲突重新展示并确认；缺字或容量超限说明具体原因；结果不明先查询，不通过重复新增或重新发布碰运气。
- **职责边界**：不自动更改其他业务系统，不把“提交结果”等同完成，不擅自清空清单，不修改字库、固件、网络配置或设备绑定。

调用脚本执行稳定、可验证的读写；Skill 负责使用规则与对话组织。两者都必须以服务返回的事实为准，只有匹配发布版本的设备显示回执才能回答“屏幕已更新”。

长清单按渠道长度限制分段展示，不能让用户确认被截断的内容。双渠道共用建议和投递记录；等待设备后实际成功或失败，通过已有投递机制反馈一次。投递结果不明先核对，不盲目补发。

交付物：Skill 包、调用脚本、对话及故障示例、双聊天入口和日报集成说明。

验收：在大圣真实会话中触发并调用 Skill，而非只通过命令行脚本测试；分别验证微信、企微提出修改与确认、跨入口重复确认、拒绝建议、修改后再确认、歧义事项、离线反馈及日报提出建议。最终由用户核对实际屏幕，确认三部分完整串联。

## 已有证据与实施顺序

Mac 经目标 2.4GHz 热点直连大圣服务器的 SSH 已验证；这不等于设备已联网，也不证明尚未部署的 HTTPS、SNTP 接口可达。先验证实际网络通路，再推进联网固件。

1. **接口与准备**：备份当前数据库、完整设备 Flash、服务器将修改的 Skill 和工作流文件；使用 `codex/` 前缀功能分支，保留现有工作。固定快照、确认及状态接口，用模拟设备验证服务和网络通路。
2. **固件排版**：生成字库，验证体积、边界和资源占用；完成文本解析、分页、绘制及缓存，运行单元测试和编译，再烧录真屏检查字号、四角、方向、按键及完整原文。
3. **长轮询联调**：迁移数据、配置联网，验证 Mac 停止服务后独立更新，以及超时、断网恢复、回执和版本保护；适配备用网页及按需截图。
4. **Skill 与日报**：先模拟接口测试，再部署到真实大圣，分别在微信、企微验证修改和确认；回放一份已有日报后接入实际 19:00 流程，完成端到端验收。
5. **试用与交付**：连续使用 3–5 个工作日，检查更新速度、断线恢复、建议质量和操作负担。执行时更新产品计划、架构、开发说明、README 及 AGENTS.md，区分计划、实现与实际验收结果。

### 长轮询专项验收

- 请求等待期间发布立即响应；25 秒无变化正常结束并立即续请求；发布恰好落在请求交接期间也不会丢失。
- 连接仍在但读取卡住时，35 秒整个请求期限确实生效；下载及回执也覆盖写入、读取不返回的场景。
- 热点断开、Wi-Fi 恢复、服务重启、HTTPS 被关闭、传输中断及设备完全断电后，保留旧清单并取得最新已发布内容。
- 回执丢失或重复提交不重复写 Flash；旧版本、校验错误、非法内容、证书与认证错误不能替换有效内容。
- 内容错误不形成紧密重试循环；重连没有重复在途请求、等待者或连接资源泄漏。网络等待不阻塞 UI，截图请求不改变清单。
- 真屏验证网络指示：首次启动、热点关闭及重新连接、Wi-Fi 已连接但服务停止、请求卡住、认证／证书错误均显示对应状态；网络恢复后先立即查询并恢复正常图标。正常长轮询等待、204 响应和请求交接不闪烁，业务内容错误不误判为断网；图标刷新不重置轮播或跳页，日期、标题无重叠，旋转及截图方向正确。
- 稳定联网且设备已开始长轮询时，以 100 条混合事项、原文合计不超过 20KiB 测试 20 次：目标至少 19 次在服务接受确认后 5 秒内显示，全部在 10 秒内完成。25 秒等待上限不是更新延迟；模型处理时间另计，断网恢复不套用在线性能目标，结果以实测为准。

### 回退与资料边界

出现回归时暂停新增发布入口，恢复旧服务、固件及字体分区备份；保留本轮新产生的任务和确认记录，核对后恢复，不能直接覆盖数据库丢弃期间修改。真实清单、地址、凭据、设备标识、原始响应和日志均留在私有配置或记录中，公开仓库仅保留脱敏实现与说明。

固件变更继续按实现与测试、授权范围内烧录、真屏验收及用户确认、Git 提交推送的顺序交付。本轮仅记录方向，未改固件、未烧录。

实施先确定文本快照、确认和状态接口，再分别完成设备与服务；Skill 使用同一接口测试。三部分独立可测，最后以“聊天建议 → 本人确认 → 服务发布 → 设备排版显示 → 聊天反馈”的完整链路验收，不用任何单部分通过替代整体完成。

## 通信技术依据

- [ESP-IDF 5.5.2 HTTP 客户端](https://docs.espressif.com/projects/esp-idf/en/v5.5.2/esp32s3/api-reference/protocols/esp_http_client.html)：采用内置 HTTP/S 客户端及连接复用；业务另外保证整体期限、重试及版本一致性。
- [RFC 6202：HTTP 长轮询](https://www.rfc-editor.org/rfc/rfc6202.html)：服务器在更新或超时后完成响应，客户端继续请求；有更新时无需等待完整超时周期。
