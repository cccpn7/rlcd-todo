# 桌面待办纸

设备通过 Wi-Fi 独立获取清单，Mac 不必在线。三份平级列表：`focus` 今日重点、`misc` 今日杂项、`follow` 今日追踪。保留原文、手动顺序；未完成事项自然延续。不要把完整周报或部门项目库自动变成清单。

使用本技能目录下的 `scripts/todo.py`。它只访问独立待办服务，保存完整接口响应再解析；配置和凭据已经部署，不要读取或回显令牌，也不要重启 OpenClaw、修改网关/定时任务或其他服务。

## 整理与确认

1. `python3 <技能目录>/scripts/todo.py state` 获取当前清单、revision、已发布版本及设备状态。
2. 根据本人的需求整理增量操作，写入临时 JSON 文件。展示新增、修改、完成、移除或排序；保持不相关事项不变。不确定事项归属或含义时先问。
3. `python3 <技能目录>/scripts/todo.py propose --file <变更文件>` 创建候选。文件格式：`{"base":当前revision,"request_key":"本次唯一标识","changes":[...]}`。同次重试必须沿用同一文件和 request_key。
4. 展示返回的建议及其确认编号，请本人回复 **`确认 Txxxxxxxxxx`**（使用服务返回的完整编号）。提出“帮我整理”或生成建议本身不等于确认；“好的”须请本人补上该编号，避免确认错清单。候选24小时有效。
5. 收到本人原始消息中的完整确认后，执行 `python3 <技能目录>/scripts/todo.py confirm <编号>`。服务会核验受信会话中本人消息；不得伪造会话、修改数据库、代写确认消息或要求绕过核验。没有有效确认时保留候选，不发布。
6. 查询 `python3 <技能目录>/scripts/todo.py status <version>`。只有 `phase=updated` 才说“屏幕已更新”；`queued` 说“已发布，等待设备连接/显示”；`failed` 说明失败，保留原内容；`superseded` 说明有更新版本。每次间隔约1秒，最多查询三次。仍等待时调用 `python3 <技能目录>/scripts/todo.py watch <version>` 注册一次结果通知，再如实回复；设备显示、失败或被新版替代后，独立服务复用既有双端投递台账通知一次。不要再自行重复推送。注册失败须说明无法自动通知，不能承诺稍后一定提醒。

409 表示清单在候选后变化：重新读取、生成新建议并重新确认，不能直接改 base 重放。重复确认同一编号是幂等的。设备离线时仍可确认，重连显示最新发布。

## 操作格式

`changes` 支持以下对象：

- 新增：`{"op":"upsert","text":"核对样品反馈","category":"follow"}`；可加 `source` 与 `source_id` 成对实现稳定去重。
- 修改/移分类：`{"op":"upsert","id":"已有编号","text":"完整新原文","category":"focus"}`。
- 完成/撤销：`{"op":"complete","id":"已有编号","done":true}`，撤销用 false。
- 移除/恢复：`{"op":"remove","id":"已有编号"}` 或 restore。删除保留历史，不凭空重建同一事项。
- 排序：`{"op":"order","category":"focus","ids":["该分类所有未完成事项编号，按目标顺序"]}`。

不要提交整份替换或手写版本；服务生成版本，设备自行排版。Unsupported character 错误应指出字符，让本人决定替换，不能静默丢字。

## 晚间建议

工作日日报结束后，可结合当天本人未完成事项整理“明日清单建议”，沿用上述候选/确认流程。只附上与个人有关的三份清单；不改日报原本章节、归档和投递规则，不建立新定时任务。跨日不会自动确认或发布候选。
